# screen-bridge

为 AI 助手提供持续更新的屏幕状态与电脑操作工具。

## 项目目标

减少 AI 每次操作电脑前重复截图、识别文字与定位界面的等待：在本地维护一份可读取的屏幕状态，让 AI 按需获取文字、位置和图片，再调用操作工具。

项目目前处于初始化与方案设计阶段，以下能力是第一版计划，尚未实现或完成性能验证。

## 第一版范围

- **平台与范围**：Windows 当前前台窗口，包括浏览器和桌面应用；窗口切换后更新状态。
- **首个接入对象**：Codex，后续考虑其他 AI 编程助手。
- **文字与界面元素**：优先使用 Windows 无障碍接口读取应用提供的文字、按钮名称和位置；不足时使用 OCR（从截图识别文字）补充。
- **持续更新**：检测界面变化，尽量只重新处理变化的内容，避免重复识别。
- **图片理解**：记录可获得的图片区域、名称与截图；需要理解内容时按需处理，复用未变化图片的结果。任意图片区域检测和具体模型接入方式仍需验证。
- **状态文件**：计划使用 JSON，记录文字、元素类型、坐标、所属窗口、采集时间、屏幕版本和信息来源。
- **操作工具**：计划提供点击、输入、滚动和按键，并检查读取状态是否已经过期，降低旧坐标导致的误操作。
- **工具接入**：优先考虑 MCP（AI 助手连接外部工具的统一接口），具体能力以 Codex 实际接入验证为准。

## 计划的数据流

```text
Windows 当前窗口
    ↓ 获取界面结构与截图
变化检测 → 无障碍接口 / OCR / 按需图片理解
    ↓ 整理坐标、时间与版本
本地屏幕状态文件
    ↓ 读取状态与局部图片
Codex
    ↓ 调用点击、输入、滚动等工具
检查窗口与状态版本 → 执行操作 → 重新观察
```

## 后续验证

1. 在文字编辑器、浏览器和一个无障碍信息不足的界面上验证采集效果。
2. 测量从界面变化到状态可读取的耗时，以及未变化时的资源消耗。
3. 检查窗口移动、系统显示缩放和窗口切换后的坐标准确性。
4. 验证旧状态检查、局部图片获取与 Codex 工具调用能否完成完整操作流程。
5. 对比现有截图读屏流程与本项目的实际等待时间，不预设提速倍数。

## 本地运行数据

真实屏幕截图、识别文字、运行日志和浏览器登录资料只保存在本地，不提交到仓库。第一版尚未提供安装和启动命令。
